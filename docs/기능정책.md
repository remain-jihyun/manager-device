# manager-device 기능 정책

## 공통 정책

### 팝업/모달 위치
- 모든 팝업·오버레이는 디바이스 화면 안에 표시 (`absolute inset-0`, 절대 `fixed inset-0` 사용 안 함)
- AppLayout: `relative overflow-hidden` 적용으로 absolute 모달이 디바이스 프레임에 클리핑됨

### 뒤로가기 vs 취소
- **뒤로가기(← 버튼)**: 팝업 없이 이전 페이지로 직접 이동
- **취소 버튼(하단)**: 취소 확인 팝업 노출 후 이동

---

## 전체 구조 (홈 / 메뉴 / 채팅)

- **하단 탭 순서: 홈(왼쪽) / 메뉴(가운데) / 채팅(오른쪽)**
- **홈 = 대시보드 단독** — 기존 홈/메뉴 중복(둘 다 메뉴 서머리)을 제거. 홈은 대시보드(전체 간반 진행률 + 반별 현황)만 노출. 메뉴 그리드는 홈에서 제거.
- **메뉴 = 8종 그리드** — 검수 / CCP / 마감 / 등록 / 채팅 / 폐기 / 재고실사 / 입고검수

## 재고실사 (InventoryPage)

### 창고 선택
- 상단에 **창고 칩 바**(가로 스와이프). 탭 시 하위 정보(헤더·요약·목록·실사)가 해당 창고 기준으로 전환
- 진입 시 어떤 창고의 몇 차 실사인지 표시: 창고명 + 온도대 배지 + 층 + 회차
- 창고 목록은 **mes-v2 기준 13개 창고**(`mockSpaces` 중 `spaceType === "WAREHOUSE"`)
- 각 칩에 현재 회차 진행도(`done/total`) 표시
- 창고 전환 시 폼 탐색 순서(order) 초기화

### 데이터
- 출처: **mes-v2** — 창고는 `mocks/type-management.ts`, 품목은 `lib/mock-data.ts`의 `mockWarehouseInspection`
- 창고별 품목은 **10개씩**(총 130개) 구성. 기존 코드(RM-001~RM-020)는 mes-v2와 동일하게 유지, 보강분은 RM-021~RM-134
- 품목 데이터: `src/data/inventory.ts` / 예상재고 = `어제재고 + 입고 − 불출`(입·불출은 mes-v2 `devFlow`와 동일 알고리즘으로 합성)

### 실사 모드 (일·주간 / 월말) — ★ 미팅 반영
- 상단 **모드 토글: 일·주간 / 월말**
- **일·주간 모드**: 1차 실사 1회로 끝 → **바로 재고 확정**. 실사한 품목은 실사값으로, **안 한 품목은 예상 재고로** 확정. (일·주간은 합쳐 하나의 모드)
- **월말 모드**: **1차 → 2차 → 재고 확정** 3단계 세그먼트
  - **1차**: DB에 1차값으로만 저장(확정 아님)
  - **2차**: 1차=2차면 **자동 확정**, 다르면 **차이 품목 리스트업**
  - **재고 확정**: (회계 담당자가) 차이 품목 검토 후 최종 확정. 확정 단계에 차이 품목 리스트 + `unitPrice` 기반 "예상 대비 금액" 차이 제공

### 1차/2차 동작 + 작업자 태깅 — ★ 미팅 반영
- **2차에는 1차 완료 품목만 활성** 노출, 미완료 품목은 **하단에 비활성(자물쇠)** 표시
- 1차 완료 품목은 창고 전체 완료를 기다리지 않고 **실시간 2차 반영**
- **작업자 태깅**: 1차·2차 각각 담당자 이름 + 이니셜 아바타 표시(2차 폼에 "1차 담당자" 노출 → 문의용). `worker1/worker2` 누적 저장

### 입력·단위 — ★ 미팅 반영
- 단위는 **품목 단위 통일 표시 + 자재별 단위(EA/kg)**. 품목 단위 ≠ 용량/용량 단위 (예: 1.8L → 품목 EA / 용량 1.8 / 단위 L)
- **박스당 수량 입력**: 박스 품목은 **박스 수 + 낱개 수 2칸** 입력 + 합계. 박스당 수량은 고정(MIS). **변동 품목(`isVariable`)은 박스칸 숨김**·단일 낱개 입력
- **검색 기능 추가**(창고 자재 多). 단 **기본은 바코드/QR 스캔 진입**(상단 스캔 바 → 미실사 품목 자동 선택)
- 빈 창고는 "연결된 품목이 없습니다" 표시

### 예상 재고·검증 — ★ 미팅 반영
- 폼에서 **예상 재고를 크게(5xl)**, 어제재고/입고/불출은 작게
- 예상 대비 **±10% 이상 차이 → "재확인하세요" 얼럿**(차단 X, 확인 후 진행 가능). 진행 시 **"재확인 필요"(`recheck`) 태깅** → 목록·확정 단계 배지

### 화면/표시 — ★ 미팅 반영
- **6인치 대응**: 상단 영역 압축(모드·작업자 1줄 + 창고 헤더·요약 1줄), 상·하단 고정 + 본문 스크롤, 어르신 가독성 위해 폰트 확대
- **시즌 종료 원재료 표기**(`seasonEnded`, "시즌종료" 배지 / 이카운트·eMIS 기준)

### 진행 순서 정책
- **목록 화면**: 항상 원래(데이터) 순서 유지 — 실사 완료해도 순서 변동 없음
- **실사 진행(폼) 화면**: 시작 시점에 **미진행 품목 우선 → 완료 품목 뒤** 순서로 고정. `다음/이전` 탐색은 이 순서를 따름(세션 중 순서 불변)

### MES 누적 연동
- 단말에서 확정한 1·2차·확정값은 키 `${창고ID}__${품목코드}`(mes-v2와 동일 규칙)로 누적
- `localStorage["mes-v2:inventory-audit"]`(`{ round1, round2, confirmed, updatedAt }`)에 적재 → 동일 origin의 MES 재고실사 화면이 ingest하여 회차 입력값으로 병합. 신규 필드는 선택값으로 추가해 호환 유지
- 관련 코드: `src/data/auditStore.ts`, 연동 대상: mes-v2 `app/inventory/inspection/page.tsx`

### 미정/후속 (🟡)
- 박스 무게 포함 여부 — 자재반/공정관리 측정값 차이(박스 무게). 단위·중량 기준 정리 필요
- 실사 입력 시 "품목 단위 + 박스에 남은 kg 동시 입력" 가능 여부 — 결론 미정

## 검수 (InspectionPage) — ★ 미팅 반영

- "스캔하면 바로 완료" → **합격/불합격 분기** 구조로 변경
- 바코드/QR 스캔 → 합격/불합격 **선택**(프레임 내 오버레이 `absolute inset-0 z-[100]`)
- **합격** → 의견 입력(**선택**) → 확정 → 다음 반으로 간반 넘김, 토스트 "다음 반으로 전달되었습니다"(`absolute bottom-24`)
- **불합격** → 사유 유형(**필수**, 선택 칩) + 상세 사유(**필수** textarea) + 사진(**선택**) → 확정(필수값 모두 채워야 활성) → 단말 상태 "작업 중" 복귀(간반 미완료 유지)
- 불합격 사유 유형 목록: `src/constants/inspectionData.ts` placeholder → **MES "유형 관리"에서 등록·관리 예정**
- 체크리스트 방식 미채택(품목 250종 부담), 불합격 → 폐기 자동 등록 안 함

## 인원 등록 (RegisterPage) — ★ 미팅 반영

- **NFC 태깅 시 반·핸드폰 입력 불필요, "사람만 선택"** (반 선택/핸드폰 단계 제거)
  - NFC 카드를 갖다 댐(모의) → NFC 키값 읽힘 → 사람 검색·선택
  - (브라우저 환경에서는 실제 NFC 대신 태그 동작을 시뮬레이션)
- **반별 리스트 대신 검색**으로 선택 (인원 80명 규모 → 검색 적합), 이름 부분 일치
- **동명이인 대비**: 결과·선택 카드에 **이름 + 부서 + 전화번호** 표시. 단 개인정보(GDPR) 위해 **전화번호 일부 마스킹**(010-\*\*\*\*-1234)
- **신규/수정 분기**:
  - 신규(NFC 키값 없음) → 바로 등록
  - 수정(기존 키값 보유, 분실 재태깅) → **"○○님은 원래 △△로 등록되어 있습니다. 변경이 맞나요?" 재확인 팝업 1회** 후 변경
- 등록 목록: NFC 키 보유 인원, 최신순/가나다순 정렬, 행별 수정·해제

## 입고검수 (ReceivingPage) — ★ 미팅 반영

- 거래처별 탭 (가로 스와이프, 50px 이상 드래그 감지)
- **바코드 스캔 → 해당 품목 표시**(스캔 시 리스트 하이라이트 후 입력 진입), `barcode` 필드
- **리스트에 없는 품목은 검색 후 선택**(프레임 내 오버레이에서 품목명/코드/바코드 검색 → "추가" 배지로 편입)
- 품목 표시에 **품목 단위 + 용량/용량 단위 + 박스당 수량**(재고실사 동일 기준): `EA / 1.8 / L / 박스당 N`
- 입고 예정 vs 실제 차이:
  - 수량 감소(diff < 0) → **미입고 / 반품** 선택. **반품은 사유 필수**, 미입고는 사유 불필요
  - 수량 증가(diff > 0) → 추가입고 / 기타
- **미입고·반품 집계 리스트는 현장 디바이스 미노출**(사무실 MES쪽). 단말은 개별 입력만, 미입고 항목엔 "사무실(MES) 집계" 안내만 표기
- **로그인 화면에 사무직 구글 로그인 옵션**(LoginPage): 현장직(카카오) 아래 구분선 + "Google로 로그인"(모의)

## 마감 (ClosingPage) — ★ 미팅 반영 (흐름 전면 변경)

- "마감 시작 → 반/유형 선택" 방식 **폐기**
- 진입 시 **점표(체크 리스트)가 처음부터 깔려 있고**, 각 점표는 **QR 코드와 1:1 매칭**
- **QR을 스캔해야만 해당 점표 활성화 — 선택 불가, 스캔 전용.** 스캔 전 점표 행은 잠김(자물쇠), 직접 탭 불가. 매칭되는 점표만 활성화되어 입력 진입(일치 없으면 토스트 안내)
- **점표마다 입력 항목 다름** → 점표별 스키마(기존 closing 입력 컴포넌트 재사용) + 사진 + 특이사항 → 완료
- 점표 목록 데이터: `CHECKPOINTS` 상수(id/이름/위치/qrCode/입력 스키마). **QR 부착 위치·검수 포인트는 생산본부장 지정 예정(🟡)**
- 입력 화면 뒤로가기: 팝업 없이 점표 목록 직접 복귀 / 하단 취소: 취소 확인 팝업 `absolute inset-0 z-[100]` / 토스트 `absolute bottom-24`

## CCP 점검 (CCPPage) — ★ 미팅 반영

- **"온도 점검" 항목 제거** — 온도 점검이 아니라 **CCP 점검**(가열/소독 등 현장 일지)
- 흐름: **점검 버튼 → 필수값/선택값 리스트 입력 → 사진 등록 + 특이사항 → 완료**(필수 미입력 시 완료 불가)
- 점검 항목: `src/constants/ccpData.ts` placeholder(가열 온도/시간, 소독액 농도, 세척·소독 상태 등, 항목별 `required`) → **MES "CCP 관리"에서 등록·수정, 생산 품질에서 확정 예정(🟡)**
- 반별 CCP 지정 + 주기(30분/1시간 등) 설정에 따라 점표 자동 생성 (`ccpStore`: `line`·`intervalMin`·`startTime`)
- 완료 항목 사진 → 리스트 썸네일(48×48), 썸네일/입력 사진 탭 시 프리뷰

## 폐기 등록 (DisposalPage) — ★ 미팅 반영

- **탭 4개: 원부재료 / 반제품 / 완제품 / 전처리**
  - **원부재료** — 바코드 스캔 + 수기 등록 둘 다(집코드 아님; 기름=바코드, 야채류=수기) → 폐기 유형 + 수량(개)
  - **반제품** — QR 태깅(모의 스캔) 또는 수기 간반 선택 → 폐기 유형 + 중량(kg)
  - **완제품** — 바코드 스캔/수기 → 폐기 유형 + 수량(개)
  - **전처리** — 유형 선택 없이 **kg(중량)만** 입력(음식물·꼬다리 등)
- 폐기 유형(원부재료/반제품/완제품): 변질·유통기한·파손·기타
- **폼 뒤로가기**: 팝업 없이 직접 복귀 / **하단 취소**: 취소 확인 팝업 `absolute inset-0 z-[100]`
- 각 탭 하단에 "오늘 OO 폐기 내역" 탭별 필터 표시

## 범위 외 / 보류 (🟡)

- **추가 불출(자재 불출) — 부분 불출 기능**: 포장단=직코드→제품 단위, 전처리반=산코드→원재료 일부 불출. 표현 방식 미정 → 생산본부가 "경우의 수" 정리·피드백 후 화면 설계. (현장 디바이스 영역, 이번 반영 제외)
